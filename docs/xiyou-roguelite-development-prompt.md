# 《大圣：无相轮回》完整开发提示词

以下正文可直接复制到新的游戏开发任务。它用于新建一款西游题材肉鸽游戏；不要覆盖现有《大圣：舍利魔塔》的目录、关卡或存档。

---

你是一支负责策划、程序、美术、交互与试玩验收的游戏开发团队。请完整开发一款面向 PC 浏览器的俯视角动作肉鸽游戏《大圣：无相轮回》，交付可以实际游玩的成品。先形成简明设计与实施清单，再连续完成实现、素材接入、合法试玩、修复与验收。不要停在策划文档、静态页面或演示动画。

## 一、剧情与玩家身份

沿用下列剧情骨架，用原创台词和演出表达，不照搬影视对白：

无天以黑莲将三界众生、十六枚外舍利和悟空的五重本心镇入十八层无相塔。乔灵儿在塔外守候。孙悟空携残损金箍棒重入塔中，点灯僧引路，途中重逢八戒、唐僧、哪吒与白衣无天，逐步明白善念、救援与取舍会真实改变归途。

黑莲会在败退后重塑塔路，形成每局不同的房间、敌群和机缘；但关键剧情因果必须稳定且可理解。每次轮回带回的线索揭开五重心印。十八层终局面对“金甲、执念、心火”三相，最后发现第十七颗“无骨舍利”就是悟空自身。

保留两个完整结局：

- **破劫归尘**：悟空化为无骨舍利，携十六外舍利破开黑莲；被亲手救回的众生将其唤回人间。
- **留灯守塔**：众生循灯离塔，悟空留下镇守黑莲余烬，成为后来者的灯。

两种结局均为正式通关，不设“选错就不算”的隐藏处罚。救援必须改变路线、支援、首领机制或结局演出，不能只是增加一个数值或改一句台词。

## 二、明确的产品与技术目标

- PC 键鼠为主要目标；先把手感、画面与交互做完整，不将时间投入广泛移动端适配。
- 使用固定俯视 / 斜俯视镜头的二维场景，表现为精致的三维材质预渲染素材。不得把“有立体 PNG”宣传为实时三维或 PBR 网格。
- 可默认采用 Phaser 3 + TypeScript + Vite；若为了独立离线运行选择 Canvas 2D + JavaScript，也须将模拟、渲染、输入、内容和存档分开。不要为了换框架而推迟可玩交付。
- 发布入口必须可离线运行，本地 HTTP 预览和直接打开发行版 `index.html` 都要实际验证。禁止运行时依赖 CDN、远程字体或在线生成接口；选择引擎时就解决 `file://` 下的模块与资源加载问题。
- 游戏世界放在 Canvas；文字、可访问操作和复杂阅读放在 DOM，二者使用同一套状态与输入模式。
- 开发辅助数据与正式存档分开。调试传送、无限资源、修改存档可以用于定位问题，但不能证明关卡可通关。

## 三、真正成立的肉鸽循环

先完成一条“进塔 → 观察敌势 → 战斗 / 绕行 / 解谜 → 选奖励 → 形成构筑 → 首领 → 失败或通关 → 新一轮”的闭环。

1. 每局保留十八层与六回剧情，房间连接、遭遇、奖励组合按种子变化。普通层由少量紧凑房间组成，每三层有一次首领或关键守关，使完整一局目标时长约 30–45 分钟；以试玩实际耗时修正，不能仅在文案里宣称。
2. 每层给出明确可执行的主目标，允许可选支院、救援、宝匣、修心和风险房。进入下一层不强制清空所有可选敌人。
3. 随机性主要用于局前种子、遭遇与奖励选择。攻击范围、敌方前摇、伤害、无敌帧、资源费用与掉落规则清楚可解释，禁止用不透明的随机秒杀制造难度。
4. 死亡结束本轮临时构筑；保留剧情见闻、可选开局流派、图鉴与外观解锁。永久成长以增加玩法选择为主，不能让失败变成必须刷数值才能通关的收费墙。
5. 没有付费复活、现实时间等待或消耗型门票。失败后短时间内可带着一个具体新认识再开始。
6. 同一种子、同一输入与版本应能复盘。记录 PRNG 状态，续档不能刷新商店、重抽奖励或重复领取资源。

## 四、战斗、神通与构筑

基础手感先于内容数量：移动、转向、受击、打断、命中停顿、闪避与首领预警必须先可玩，再增加敌种。

建议操作：WASD / 方向键移动，鼠标瞄准，左键棒击，右键闪避，1–3 使用已装备神通，F 执行场景交互，I 行囊，J 手记，Esc 暂停 / 返回。所有交互统一使用 F，不再混入 E。提供清晰的当前按键提示，并避免键位与页面滚动、浏览器快捷操作冲突。

四种标志性能力必须改变实际玩法：

- **火眼金睛**：识别幻壁、敌势与伪装，揭示首领破绽或特殊路线；查看基础规则不收资源。
- **金箍架桥**：延长棒击、越过断口或架出临时通路；不同升级在攻击范围、击退、连段与地形收益间取舍。
- **青蝉化形**：以清楚的持续时间 / 费用穿过铁栅、潜入或躲避特定招式；不要变成可无限保持的全面无敌。
- **毫毛分身**：牵制、协击或驻守阵眼；分身数量、维持条件、召回和重部署费用明确，解谜不能因永久损耗陷入软锁。

至少做出三条有不同操作和资源逻辑的构筑，例如棒势连段、神通循环、分身阵法。每条都有能在一局内完成的核心组合；稀有掉落是变化而非“拿不到就不能玩”。奖励以少量可比较选项呈现，描述包含实际触发条件、收益与代价。避免把同一效果换名称当作不同遗物。

六件标志法器可沿用定海铁、莲灯芯、照骨齿、听潮贝、心炉烬、双影镜的意象，但重新围绕动作肉鸽设计联动。例如增加棒击范围但降低回息、强化分身但缩短驻守、削弱法术反击但牺牲近战爆发。负作用在选择前展示，不能隐藏在图鉴里。

生命、灵息、疗伤物和本轮功德均有限。莲灯提供可比较的修心、治疗与换装；花费后立即显示变化，并保留下一步目标。不得用悄悄补满资源掩盖路线或平衡问题。

## 五、首领与十八层剧情节奏

六回各有独立的场景主题、敌势和机制，后续组合复用已经教过的规则。第一层只教移动、一次观察、一次战斗 / 绕行和一次奖励选择；不要开局同时铺满所有面板和长说明。

最终“心猿三相”有专属玩法，不是普通怪物血量翻倍：

- 金甲相：读势、破甲与击退边界。
- 执念相：分身真假、回响路线与安全站位。
- 心火相：风险输出窗口与此前救援带来的支援。

将一路获得的心印化成三印选择 / 布阵。布阵是免费预览；明确迎战才结算准备物。三相切换有不同轮廓、动作与音效，伤害来源清楚。即使缺少某件随机法器，也存在基础能力可以完成的解法。

过场分为入层、心印、救援、首领转相、最终觉醒与结局。用少量清楚的镜头、人物姿态、环境变化和声音讲剧情，不用一页大段文字代替演出。普通拾取与重复技能不反复打断操作。

## 六、统一的玄金古寺美术

默认画境为**玄金古寺**：湿灰石、炭黑寺构、磨损古铜、克制旧金、暗朱披帛、少量玉色灯火。冷环境光配左上暖光，明确接触阴影和物体体量。

悟空、敌人、NPC、道具、地面、建筑与界面物件必须使用同一镜头、光向、粗糙度、饱和度和体量标准。主角不能像高饱和卡通贴纸贴在写实地图上，也不能靠染色滤镜或整图模糊补救。

人物保持悟空、金箍棒、冠饰、尾巴和披帛的辨识度；用真实层叠甲片、暗金磨损和低饱和暗朱布料融入古寺。长棒、冠翎与披帛不能夸张到遮住相邻目标；通过姿态、轮廓和适量亮边辨认角色，不用持续发光描边代替设计。

重要位图素材使用 ImageGen 实际生成并落盘。角色动画从统一角色种子生成整条动画 / 同套方向帧，按统一缩放和脚点整理。保留原始透明图和生成提示；技术脚本只做裁片、共享缩放、锚点和打包，不绘制替代素材或把旧小图放大冒充高清。

出生点必须是实际可走且无实体占用的空地。人物脚点、碰撞、点击轮廓和接触阴影一致；建筑嵌入地面，楼梯有开口，道具底座与所在铺地协调。不能为了看上去通畅而绘制不存在的可走道路。

另保留**青绿壁画**作为通关奖励：未完成一次完整主线前，默认并仅提供玄金古寺，屏蔽另一画风入口；URL 参数、旧偏好和调用切换 API 都不能绕过。完成任一正式结局后解锁，刷新和新一轮仍保留。练习关、独立挑战、调试“获胜”标签不能充当通关证据。画风只影响表现，不改变碰撞、战损、资源、构筑或存档。

## 七、必须落实的游戏交互准则

这些来自实际试玩反复暴露的问题，必须直接变成实现约束：

1. **普通交互在场景里发生。** 对话、战损预览、开门、机关与物品反馈贴近对象或使用短横卷，不能做成网站广告式模态框。
2. **管理进入完整暂停体验。** 行囊、人物、手记、法器、契约与设置不做右侧长软件面板。用行囊布、经卷、灯前供签等有世界身份的构图，保证返回后继续当前场景。
3. **每个目标有一个明确主动作。** 普通人物只有交谈，碑文只有读碑；完整背景统一在手记。禁止给人物并列“交谈 / 详察 / 推演此处”。真实开路、交易等有独立结果的动作需要明确命名与后果。
4. **先比较，再确认。** 选奖励、换法器、布阵、回溯、开有代价的门均先展示结果。鼠标悬停、方向切换、查看和取消不支付；明确确认只结算一次。防止连点穿透和按键重复。
5. **一页对白一个意思。** 正文以最多约 36 个中文可见字符为基准，关键词突出。Space 先补全再推进，Esc 明确结束；末页只留一个结束动作。结束后清理旧目标和焦点，不能再次弹回同一张对话卡。
6. **目标一直可找。** 入层明确展示当前层的行动目标，并要求玩家确认。常驻要事、人物提示、手记和地面定位引用同一数据源；查看人物时可将目标移入签页，不能让两张牌相互遮挡。
7. **布局以文字实际位置验收。** 为木框、铜饰、卷轴端头留出不可书写区，不能只检查容器有没有溢出。长文只滚正文，边框固定；短窗口不能把说明 flex 压矮，让余量文字掉出框外。
8. **按钮属于所在物件。** 暗绢使用铜色刻线，纸面使用朱色刻线；主次清楚，避免再套一层软件矩形。点击区至少约 42px；普通说明不少于 14px，短对白建议 18px；少量按键注记可更小但要清楚。
9. **输入有唯一接收者。** 探索、对白、奖励取舍、暂停、入层、演出互斥处理输入；暂停不移动和施术，Tab 留在活动界面，Esc 回到正确层级并恢复地图焦点。
10. **表现消费已结算事件。** 技能和过场只读取引擎结果；跳过、快进、减少动态不重复收钱、伤血、发奖或触发能力。普通技能默认短表现，首次与关键剧情可完整演出。
11. **真正的规则使用真正的数据。** 物品预览、敌人前摇、费用、掉落和首领阶段由同一规则产生。推演 / 标记须对应目标本身，不能因为与玩家坐标相同就把随身补给误算成人物的动作。
12. **表现有辨识度。** 命中、格挡、治疗、失败、开路与升级不能都播放同一束粒子；主要信息不能只靠颜色区分。

## 八、存档、轮回与可复盘性

每轮存档记录版本、种子、PRNG、房间图、敌人状态、获得物、选择、救援、资源与正式行动结果。元进度单独保存，包含已见剧情、开局选择、图鉴和已解锁画境。

自动存档与手动存档独立；死亡不能覆盖最后一次可用的正式进度。读档恢复真实地点与当前目标，不重复播放奖励结算。版本变化时提供有据迁移，不重复扣费、重复领取或把玩家放进墙、敌人、灯台和道具中心。

可做战斗训练与独立试炼，但必须和主线进度、通关奖励与统计隔离。不要把模拟观察、脚本数据或自动化检查填写成人类玩家反馈。

## 九、实施顺序与验收交付

按下列顺序完成可游玩的纵向切片，再扩展到完整十八层：

1. 第一层：统一美术的出生空地、移动、瞄准、棒击、闪避、一种清楚的敌势、一次奖励取舍、莲灯、F 交互、短对白和保存读取。
2. 前三层：至少三种敌势、三种互有差异的构筑起手、第一次首领、第一次心印与失败再开。
3. 中段：随机房间图与可达性、有限资源、救援与支路、法器联动、机关神通、独立试炼。
4. 完整六回十八层、三相最终决战、无骨觉醒、双结局和通关画风解锁。
5. 回归并修复真实画面中的输入、遮挡、文字边界、资源结算、存档和性能问题。

至少检查 629×678 的窄 PC 面板，以及 1280×720、1440×900、1989×1113。截图必须逐张按原尺寸打开；同时检查默认态、展开态、长文、禁用、选中、取消、返回和卷末。不要一次性发送大批图片。

自动化应覆盖可达性、种子复盘、费用一次结算、暂停输入、保存恢复和通关解锁；真实游玩必须覆盖完整的一局失败与重开、至少三种构筑、合法十八层与两个结局。模拟传送、注入资源、源代码断言或“按钮存在”不能代替这些证据。

交付时给出：可玩的本地入口、完整源码与本地素材、生成提示和素材登记、规则 / 房间 / 构筑数据、实施与验收文档、代表截图、实际运行过的检查及剩余缺口。区分实现完成、程序验证、实际画面复核和真人体验，不以测试数量宣称“已经好玩”。

保持持续实施，必要时自主修正常规实现问题；只有缺失关键输入或不可逆的外部操作才需要提问。最终交付必须是可玩的游戏，而不是让用户继续选择如何开始。
