## 模糊的具体路径

当前地图缓冲为 **1008×1008**：21格×16世界单位×3栅格倍率。`sprite()` 先把角色图集画入该缓冲，`draw()` 再将缓冲的视口区域放大到最终canvas。material两次都启用平滑；DPR2最终canvas虽然是5050×2416，中间图并没有相应增加细节。

例如当前近观的格宽75.5 CSS像素：悟空原帧先按1.5倍写入缓冲，再按1.5729167倍放大到屏幕；DPR2又把最终采样放大为物理像素。96×96文件尺寸也不能代表角色有96×96细节，因为大部分区域透明。悟空帧只有1043个非零alpha像素、417个alpha≥240像素；小妖分别为734和392。此数据用于定位有效图像尺寸及透明度，不把合理的轮廓抗锯齿、影子或特效透明度直接判为缺陷。

新资源需要从原始生产源图重新取样并保留有效细节；把既有96像素图放大后改标为384像素，不能证明细节提升。角色与敌人应从图集直接画入最终DPR上下文，地形缓存可以保留。最终还需在100%显示比例下审查脸部、冠饰、轮廓及与地面的分离，不能仅以“有高清字段”或“已关闭平滑”宣布清晰。

## v7 可见通过标准

1. **探索画面由真实地图覆盖。** 默认和F近观的常规状态，21×21真实地图投影覆盖视口至少99.9%，四边缺口不超过1 CSS像素。覆盖统计取世界地图的投影矩形/实际绘制区域，包含地图内的地板与墙体，排除远景及虚构可走地形。若南沿合法入场脚点被固定技能条遮挡，采用下述明确的不可走边界石墙带例外并分开报告覆盖率，不能仍声称21×21占100%。若保留M全图规划，它必须明确标为规划模式，单独记录其行为，不能用其截图代替探索覆盖结论。
2. **清晰度有渲染链和图像证据。** material角色/敌人直接进入最终DPR上下文；记录原始有效alpha包围盒、CSS尺寸和物理尺寸。目标是在最大桌面探索视口中，有效源像素至少覆盖约1个CSS像素（CSS/source倍率≤1.05），并如实报告DPR2下的物理倍率。mural保留像素采样特征；material保留连续材质轮廓。两个风格分别审查，不用同一个平滑开关评价两种美术。
3. **目标提示确实锚定。** 普通战前符签出现在目标周围，有明确指向关系；正常无遮挡状态下，符签与实际目标包围盒的最近间距不超过 `max(32px, 0.5格)`。必要的避让采用其他象限，不跳回固定右上窗。目标离开视口时隐藏或提供明确的边缘定位指示。符签不得覆盖目标或悟空的脚点保护区（半径 `max(12px, 0.18格)`）。相机移动、尺寸变化后，符签以同一已渲染投影更新。
4. **技能栏底部居中。** 桌面、手机竖屏和横屏的技能栏中心相对视口中心误差≤2 CSS像素，底部安全区有效；不与触控方向键、交互键或目标符签产生不可用遮挡。每个技能仍可实际选择、显示消耗/锁定和执行。
5. **规则及状态可信。** `screenPoint / cellAt / pickCell / anchorFor` 对同一已渲染投影一致；点击真实越格sprite上部仍选中正确逻辑实体。视觉切换、镜头及提示布局不改变权威state；手动/自动存读档保持资源和进度。保留首次接触预览、重复方向/E及Space不误战、明确新E或迎战按钮结算的规则。

外部来源、设计准则及其适用边界由主控补充；正式审查时逐项与上述实测条件对齐，不能用文档存在代替实施通过。

## 实施中发现的南沿脚点例外

主控和renderer用合法上楼entry `(10,19)` 实测发现：在1440宽和手机上，仅把相机严格限制在原21行内，会让脚点落入固定底部中央技能条。最小格宽48能保护出生点，不能保护全部上楼入口。

新的具体取舍是：技能条保留底部中央及正常体量；只有南沿脚点与技能条加12px保护区重叠时，镜头向南额外偏移不超过1.5格。露出的最多两行使用同章不可走石墙，碰撞仍由 `engine.getTile()` 返回 `#`，不加入远景、云层或新道路。material缓存允许扩为2016×2208；像素缓存为1008×1104。M规划不使用此偏移。

正式报告分别列 `authored21Coverage`、`boundaryWallCoverage`、`offmapSceneryCoverage`。常规无保护偏移时要求前者≥99.9%；保护个案要求前两者之和≥99.9%、远景覆盖为0、所有可见越界格仍为`#`，且悟空脚点位于技能条上方至少12px。报告给出同一合法entry的未保护几何/反例及保护后实测，不把保护后的边界石墙带称为原关卡内容。
