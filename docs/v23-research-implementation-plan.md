# 大圣舍利魔塔玩法深化实施方案

2026-10-24。下一阶段集中推进三件事：用已有神通和有限资源构成更丰富的局部问题，让章节完成有清楚的结果，让重玩能公平比较不同策略。v22 的短程推演、章回回退、熟路快行与配装比较继续作为基础使用。

本方案承接 [相近游戏玩法与反馈调研](v20-similar-games-research.md)，并以 [v22 实施验收](v22-playability-review.md) 为当前基线。这里定义后续实施顺序与交付条件；本次只形成方案，没有修改游戏运行代码、地图、数值或存档。

## 一 调研结论与本作取舍

调研选取五款游戏和十条历史玩家评论。开发者说明用于确认玩法，评论用于理解个体体验；这组材料适合提出设计假设，不能当成留存率或普遍偏好的证明。来源与样本见 [调研索引](../research/playability-v20-sources.json)，以下保持其原有来源范围。

|参考游戏|可迁移的经验|本作后续实施|
|---|---|---|
|Tactical Nexus，调研 2.1 / S01–S02|固定局面、可比较的状态和低成本重试支持策略探索。|提供独立于主线存档的短篇挑战，公开相同起点和目标，用资源结果比较策略。|
|DROD RPG，调研 2.2 / S03–S04|跨区域规划需要局部问题的收束，完成一段后应知道改变了什么。|每个样板遭遇形成“看到问题—比较路线—行动—看见后果”的完整闭环；章末复盘具体通路和取舍。|
|Desktop Dungeons Rewind，调研 2.3 / S05–S06|探索可以承载资源价值，表现应保护全图识别和预测。|把现有成长、补给与战序联系起来；同屏看清机关联动和真实战损，保持有限生命，不加入走路回血。|
|DungeonUp，调研 2.4 / S07–S08|重复清理和隐晦前提可能增加疲劳，跨局加成会影响成绩可比性。|前置公开长期用途，压缩已知路执行；挑战不发放永久属性，不要求清怪或查隐藏解法。|
|Into the Breach，调研 2.5 / S09–S10|公开后果仍能产生丰富的取舍，目标变化可以支持复玩。|用救援、保钥、有限驻守和不同通路构成公开目标；同一场景提供不同任务条件，不加入随机命中或反应限时。|

## 二 当前基础与需要补齐的部分

当前八个关键运行文件与 `audits/v22-final.json` 的登记哈希一致。v22 已有：本层最多三步的只读推演、当前已拥有法器的组合比较、六章起点与有限取舍记录、整份状态回退、熟路快行、会话阶段回看。v21 已有：短分镜、三相动效和最终战三印布阵。这些能力继续保留，不重新立项。

下一阶段补齐两类内容：**新的组合遭遇关系**，以及**与主线隔离的同条件重玩**。同时用真人观察检验现有工具是否容易理解，避免继续增加入口和说明负担。

路线比较先统一起点与完成条件。`audits/v22-branch-routes.json` 中，八层两路都取得外舍利，但普通路还激活了定风扳杆、取得了额外成长，栈道路尚未完成相同机关条件；这能证明两路可达，不能直接证明两路同样划算。十一层两条记录都到达下一层，但攻击、防御、功德与补给存在差异，适合进一步比较。本阶段把“完成条件相同”列为路线平衡的前提。

## 三 优化范围与设计约束

保留十八层主战役、确定性战斗、有限生命与道具、两套画境、直接打开 `index.html`、F 交互 / R 归位 / T 推演。继续使用现有 Canvas 与 DOM，以及引擎和表现分离的结构。

普通对白、机关、开门和战损留在游戏场景中。挑战选择、成绩比较和章末详细复盘使用现有完整暂停体验，退出后恢复输入与地图焦点。当前主目标保持可见，过场只读取已结算事件，跳过不重复扣费。

本轮后续实施范围包含三个样板遭遇、两个首发挑战和必要的记录隔离。随机地图、联网排行榜、永久刷属性、手机全面适配与更换引擎不纳入。

## 四 三个样板遭遇

下面给出具体设计方向和资源边界。地块位置与固定数值在合法路线推演后确定；不能把尚未验证的候选布局称为已可玩。每个样板先在独立试炼中验证，再决定是否合入主战役。

### 样板一 第八层渡路与成长时机

**要让玩家思考的问题：先取得攻击成长减少后续出手，还是先取得补给承担当前战损，是否值得花黄钥换取避战通路。**

当前已有水轮、低水西渡 / 高水东渡、渡灯契约、赤铜灵晶 `f7-10`、小蟠桃 `f7-8` 和听潮贝。第一遍到八层时只具备架桥和化形，分身尚未觉醒，因此新主线解法不能要求分身。

候选布局将现有赤铜灵晶与小蟠桃放入两条渡路各自的收益链，把“先取得什么”与下一场守卫的战损临界联系起来。渡灯栈道继续保留黄钥与放弃仙桃的公开代价，不能同时免费收走两条普通路的全部奖励。调整只移动已有供给和阻挡关系，不增加资源总量。

实施前先把两种普通渡路与供灯路线都推到同一终点：取得本层舍利、满足定风条件并具备上楼资格。记录沿途全部自动拾取、机关、补给、战斗和选择；比较生命、攻击、防御、各色钥匙、功德、灵珠与桃，行走步数单列。

**通过条件：**同一合法起点、同一任务终点下存在至少两条有资源权衡的路线；若一条在全部重要资源上都更差且没有独立目标收益，就调整该路线。再从不同的合法生命和配装起点复核，确保不是只有一套预设属性才成立。切水位不能困住行者，也不能关闭必要退路。

### 样板二 第十一层驻守与补给顺序

**要让玩家思考的问题：两道影子应该先开补给、先开经室，还是直接保障上行。**

保留两分身上限、甲乙开上行、甲丙开攻击经、乙丙开护身经、经卷互斥和取卷后退路常开的约定。新增关系优先使用已有补给位 `f10-9` 或 `f10-10`：让一处补给的可达性依赖驻守组合，使“先取补给再换阵”和“先取经卷再重排”有不同的灵息与生命预算。

先制作一处可撤销的布局原型，不增加第四镜台、不缩减免费收影能力、不把调度变成重复按同一技能。若已有布局只靠补给位置调整就能形成新问题，沿用现有机关规则，不新建机制系统。

联动预览在选中镜台时标出将开启、将关闭与取卷后保持开放的门。显示实际施法费用和驻守数；有双影镜时必须按当前配装重算。普通状态只显示当前相关关系，完整说明按需展开。

**通过条件：**攻击经与护心经均有从章起点获得的合法通关记录；至少两种顺序在资源或目标上有实际差异。取卷后都可退出经室、回收丙影并重建甲乙；补息、撤销、读档和重新分配不能绕过两影上限或复制经卷。

### 样板三 十四层至终战的取舍回报

**要让玩家思考的问题：一次救援和一件法器改变了哪些后续问题，保住的资源能怎样用于最终战。**

先完善现有两段因果：十四层七伤护送的 70 生命与 20 功德修身，分别连接十五层援手侧路与正面路线；十七层留髓 / 燃髓，连接护身成长、心炉烬取法与十八层三相准备。

在取舍地点把后果和真实目标连接起来：显示会接通哪条侧路、绕过哪个守卫、放弃哪份成长，以及尚未满足的条件。未到达的楼层只说明已公开的用途，不提前展示整层最优路线。到达后用实际场景变化回应此前选择。

只在前两处样板证明有效后，再考虑重排这里的可选遭遇。保留主线原有合法路线和自由结局；不增加隐藏善恶值，不以救援选项自动决定结局。

**通过条件：**从同一合法十四层起点记录护送 / 修身的对应十五层终点；从同一合法十七层起点记录留髓 / 燃髓到最终战后的结果。两段都公开成本、获得物与放弃物，整场预览和实战一致。玩家能说清至少一项后续收益。

## 五 独立挑战与公平记录

### 首发内容

先把现有八层和十一层制作成两个可完成的短篇挑战；新布局通过后以新的题目版本加入，不覆盖旧题目。每题首发只配两个公开目标，后续题目按玩家理解情况扩展。

正式版本在主线完成对应样板后解锁挑战，入口显示明确条件，避免提前泄露后段谜题。解锁由主线的正式完成状态产生；挑战成绩不解锁主线奖励。旧档按已完成条件识别，不要求玩家重走已完成章节。

|挑战|共同起点和完成条件|可选目标|
|---|---|---|
|弱水取舍|同一份由合法战役动作生成的八层起点；取得舍利、接通定风、到达上行资格点。|保留指定黄钥完成；或通过渡灯栈道完成。两目标分别记录，不混排名。|
|两影同渡|同一份合法十一层起点，公开两影、灵息和已有补给；取得一卷并以甲乙驻守到达上行资格点。|取得攻击经；或取得护心经。可比较各自资源结果。|

关键代价在开局就说明，包括黄钥消耗、放弃的治疗、同时驻守上限和经卷互斥。候选时长为一段短篇体验，不用强制倒计时限制思考；实际时长由试玩确定。

### 主线与挑战隔离

挑战使用独立运行会话。建议以 `RunSession` 承接运行模式、起始状态、规则版本、存储空间、目标与输入路由；正式行动仍由 `TowerEngine` 结算。v22 的 `persist:false` 只够支撑只读沙盘，不能单靠它承担挑战的保存、回溯与恢复。

进入挑战前保存主线的完整状态与章回档案；挑战中的自动保存、Ctrl+S、L、导入导出、新游戏、撤销与重做全部指向挑战会话。中途刷新也要恢复正确模式。退出挑战后读取原主线会话，资源和章回记录必须逐字段一致。挑战奖励与成绩只保存在挑战命名空间，不能写入主线。

题目按目标限定区域，在引擎动作边界约束塔阶、乘云、传送与结局入口；不能只隐藏按钮。完成时在资格点正式结算目标。起始状态由开局合法动作脚本生成，并登记脚本、状态与规则哈希，避免手工捏造不可达属性。

### 记录比较

每条记录绑定题目、目标、起始状态哈希、内容修订和规则版本。只有这些条件相同的记录才能比较；自定义导入局面单独标明，不进入标准记录。

结果保留完整资源向量：生命、攻防、各色钥匙、功德、灵息、灵珠、桃和目标救援集合；战损与步数作为补充，不把击杀数或速度作为唯一分数。优先展示“保留更多生命”“保住一把青钥”“本次多耗一珠”等可解释差异。

对同目标记录，只在某条方案所有比较资源均不差、且至少一项更好时称为更优；互有得失的方案并列保留。规则或起点变化后分开记录，旧版本成绩仍可查看。撤销允许试错；标准成绩可标注是否使用回退，不宣称本地记录具备线上防作弊能力。

## 六 章节结果与界面收束

将“此行所得”的即时提示延伸为简短的章末回顾，优先使用真实选择和已救人物。主线在自然章末显示一条具体结果及下一步用途，玩家主动打开时才展开详细账目；挑战在达标时展示目标、代价、所得与再试一次入口。

每条结果必须能追溯到正式状态或行动记录。例如“护送花费 70 生命，十五层侧路已开放”“保住青钥，化形消耗 1 灵息”。条件尚未完成时保留未完成状态，不能把计划或推演写成已经发生的故事。

必要的跨会话回顾进入结构化行动记录，保留时间顺序、目标引用和资源差值；避免从会被截断的日志猜测历史。恢复旧章时，后续回顾随同回退；一次返回原进度后恢复原回顾，不能跨分支拼接。

每次合入保留上一稳定修订和可恢复的存档备份。回退代码时使用匹配修订的存档与题目记录；不同规则的成绩不能混用。

## 九 验收方法与效果判定

### 功能和路线

1. 每处样板保存从合法开局抵达起点的动作，以及每条解法的完整动作和资源变化。统一达标条件后比较，覆盖缺钥、低生命、灵息不足、不同配装、回收和放弃支路。
2. 使用两条现有完整战役路线作为回归种子。布局调整后若动作失效，说明具体原因并重新走出合法路线，保留旧记录；不能通过降低检查或注入资源得到“通过”。十八层、两种结局与三印终战均要走通。
3. 覆盖主线 / 挑战之间的进出、刷新、手动与自动档、导入导出、撤销/重做、章回恢复、返回原进度及版本升级；主线完整状态与章回档案在挑战前后保持一致。
4. 两套画境分别检查 1280×720、1440×900 和宽屏的代表状态；逐张打开原尺寸截图，检查守卫、目标、联动门、数字与主动作。验证 Esc、Tab、F、R、T、长按和演出跳过。
5. 在断网的 `file://` 下验证主线、挑战、记录和恢复。测量真实改动后的启动与输入耗时；发生可复现退化再定位优化。

### 真人观察

安排约 6–8 名中文 PC 玩家，覆盖熟悉魔塔和初次接触两类。先观察 v22 的首三层与十一层，再用相同任务观察样板。不同玩家平衡体验顺序，减少熟悉地图造成的偏差；记录录像中的思考、观察新信息和熟路执行，分别统计。

|问题|首轮探索门槛|未达到时怎样调整|
|---|---|---|
|是否理解公开代价|至少三分之二参与者能自行说明一条路线的收益、支付和放弃物；按实际人数报告。|缩减分散说明，将关键信息放回目标旁。|
|是否形成不同计划|每个样板至少出现两种有依据的合法计划，参与者能解释选择原因。|检查是否存在明显劣解、纯执行机关或只对某套预设属性成立。|
|是否感到一段已经完成|多数参与者能说出刚改变的一项通路 / 救援结果及下一步用途。|调整阶段收束点和实际场景变化，避免只加通关文字。|
|是否减少无信息执行|同任务中熟路纯执行时间相对基线争取降低约 20%，同时保留需要判断的中断点。|分析具体回跑段，调整布局或安全行进，不自动代做关键动作。|
|是否理解重玩目标|参与者能区别两种目标；至少观察到主动尝试另一目标或另一计划的行为，并记录原因。|调整目标差异与回顾，不用永久加成催促重玩。|

人数、三分之二和 20% 是本作拟定的探索标准，不是竞品数据或留存承诺。功能验收、理解度和主观偏好分别记录；一轮小样本不推导整体留存提升。
