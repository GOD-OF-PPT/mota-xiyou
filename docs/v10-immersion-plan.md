# 沉浸式 PC 交互：调查、准则与验收目标

2026-10-22。承接 v9 文档全部问题，并重新打开用户最新三张截图。v9 的“已验证”只说明对应动作和规则可运行，不再作为整体交互体验已经完成的结论。

## 系统问题

1. 修心、行囊、人物、手记和设置共用侧栏容器；修心还混入整套法器说明，导致长页、滚动与地图脱节。截图 1 是直接反例。
2. 对话把多个叙事目的塞进同一段，自动剧情和主动交谈又有两套呈现。缩短动画时间、换金边都不能解决信息优先级。截图 2 是直接反例。
3. 目标框统一限宽，却同时放三个操作；条件未满足时仍占位一个禁用动作，标题截断、汉字逐列换行。截图 3 是直接反例。
4. 入层提示被自动对白、重绘及短时消失掩盖；“曾经发出事件”没有证明玩家看到、理解了这一层的目标。
5. 技能效果局限于小格，容易被人物、提示或下一次移动盖住；没有完整、可辨认的动作过程。
6. 输入缺少统一的模式规则。探索、对白、修心、行囊和演出要明确谁接收方向、数字、Space、Enter、Esc，退出后还要恢复地图焦点。

旧文档中的门/怪物用途、白衣帮助、通关路径、旧档保护、全屏地图和双画境继续保留在回归范围；本轮不以改这些规则补偿交互问题。

## 已读取的设计依据

|原文|核实的原则|本作指导|
|---|---|---|
|[Unity：UI 与沉浸感](https://unity.com/blog/games/how-to-immerse-your-players-through-effective-ui-and-game-design)|界面要符合游戏身份、使用情境和美术方向；交互与叙事可以共同构成世界内的界面；过量文本影响节奏。|莲灯使用场景修行仪式；行囊采用角色布囊和法器阵位；管理界面不再使用长侧栏。此布局是本作设计选择，不声称所有游戏都禁止侧栏。|
|[Game Accessibility Guidelines：重要词高亮](https://gameaccessibilityguidelines.com/highlight-important-words/)|过量文字妨碍理解，突出关键词和更小的信息单元有利于快速抓住重点。|一句对白只传达一个意思；人物、神通、目标关键词突出，当前要事独立显示。|
|[Game Accessibility Guidelines：清楚简洁的语言](https://gameaccessibilityguidelines.com/use-simple-clear-language/)|保留作品语气，同时避免不必要的长度和复杂表达。|西游对白保留角色口吻，操作说明直接写动作、费用和结果。|
|[Game Accessibility Guidelines：交互式教学](https://gameaccessibilityguidelines.com/include-interactive-tutorials/)|在实际玩法中把操作与说明结合，比一整页说明更利于理解和记忆。|移动、查看、取舍利、上楼按真实进度逐步提示；完成后更新，不强制演练、不赠送测试资源。|
|[Microsoft XAG109：目标清晰度](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/109)|玩家应有简单的方式知道当前目标，目标和进度需要清楚可查。|每层入场给本层要事；探索常驻一条下一步，完成后立即变更；可定位真实目标。|
|[Riot：Clarity in League](https://www.leagueoflegends.com/en-us/news/dev/clarity-in-league/)|表现帮助辨认动作、机制与方向；注意力强度符合重要性，控制视觉噪声。|金箍、青蝉、分身使用不同动作轮廓；中屏横向演出只在成功动作后短暂出现，并回到实际场景状态。|

数值是本作的验收选择，并非把来源中的通用原则冒充固定行业标准。

## 本轮目标与验收

|目标|交付行为|通过条件|
|---|---|---|
|T1 统一界面与输入|探索、修心、行囊/人物/手记、对白、入层、技能各有明确模式|菜单和修心期间不误移动、误施术；Esc 可退回；焦点恢复；没有普通交互长侧栏。|
|T2 莲灯与行囊|场景莲灯显示简洁修行选项；行囊以中央布囊、物品和六器位置组织|不滚动即可看到三项修行、价格和资源；行囊可真实用药、配装；不足条件说明可读；费用只结算一次。|
|T3 对话与引导|短句、高亮关键词、当前要事、逐步教学|一页最多 36 个可见字符；不要求通读背景才能知道下一步；Space 先补全再翻页；主动交谈只有一份对白。|
|T4 每层入场|场景片名、氛围、当前目标及明确继续操作|18 层均实际触发；可确认、可跳过；不被自动对白盖住；读档提供当前层恢复提示。|
|T5 目标交互|标题完整、条件优先、一个主要动作|用户截图中的归根匣没有逐字窄列、无意义禁用操作；按钮至少 40px 高；预览和取消不消耗资源。|
|T6 神通演出|中屏短横带＋原场景目标反馈|棒伸长架桥、青蝉缩形穿栅、毫毛分化落阵可分别辨认；失败动作不播放成功；跳过和减弱动态不改变结算。|
|T7 持续验收|来源→问题→改动→实机→反思有记录|以三张用户反例为固定检查点；PC 两种实际视口、两套画境，截图逐张按原尺寸查看；关键操作通过真实鼠标/键盘；通关只用合法行动。|

实施顺序：统一模式与入口 → 莲灯/行囊 → 对白/入层/引导 → 目标提示/神通 → 截图反思及回归。未实际验收的项保持“待验收”，不凭元素存在、测试数量或旧报告销项。


## v12 演出补充准则

四种神通使用可辨识的动作阶段；心印、首领、觉醒与结局可使用独立过场。统一由已结算事件驱动，Space / Enter / Esc 可跳过，演出时阻断世界输入和自动行走。楼层动画必须收束为实际目标并等待确认；系统中途要求减少动态时立即停止动画，不能顺带确认入层或重新结算。实施与证据见 `docs/v12-cinematics-review.md`、`research/cinematics-v12.json`。


## v13 节奏与剧情补充

神通默认在本次游玩内首次成功时完整演出，重复使用保留场景光效与真实费用提示；设置允许每次完整。关键剧情按三镜短对白组织，结果与下一步操作留到末镜，不引入新结算。回访揭幕可以缩短，但不得移除明确确认。宝箱状态标记与图标轮廓分开，不遮挡锁扣，也不把未满足条件的匣子表现为可领取。详见 `docs/v13-experience-review.md`。

## v15 取舍与返回补充

路线契约与一次性成长先比较、后确认：点击、数字和方向键仅选择比较项；独立确认按钮或 Enter 才可结算，Space 保留按钮本身的动作。收益、支付和机会成本分别说明；费用不加表示收益的正号，付费前展示余额变化，回访说明应反映法器是否已取得。场景签页避让行者和契台，不使用大椭圆遮罩。仪式期间阻断世界快捷键及重复输入，Tab 留在仪式；点击外部只取消本次比较。行囊必须返回原未确认选择，读取最新资源条件；成功确认后回场景，防止连续点击穿透。详见 `docs/v15-choice-review.md`。

## v16 场景衔接补充

高清图片接入后，仍须单独核对地面、底座、落脚、光向和建筑开口。固定机关的基础沿用当前位置的铺地纹理；接触阴影、轮廓投影和源帧落脚同步。下楼梯必须体现嵌入地面的深度，不能只摆一座凸起台阶。装饰只影响绘制，不增加可走格或阻挡；操作提示不得压住入口。新图继续按同视口、原尺寸检查，并保留另一画境与离线流程。详见 `docs/v16-world-cohesion-review.md`。

## v17 连续玩家体验

目标、前置条件、结果和下一步统一从只读旅程模型计算；入层、常驻目标、手记与地面标记共同引用。首段用真实附近成长引入战损比较，建议不强制。G 标记只显示目标和安全路线；断口路线止于岸边。远距离按钮明确整条命令，不能用“接近”掩盖自动交互。资源反馈在结算之后出现，法器入囊与佩戴生效分开；载入和回溯不重报奖励。普通回响不阻塞探索，关键演出只保留一份。验收须含新游戏连续首段操作，并与十八层的共用流程回归分开记录。方案和交付见 `docs/v17-player-journey-plan.md`、`docs/v17-player-journey-review.md`。

## v19 莲灯布局补充

共用仪式容器切换目的时必须清理专属状态；取舍的数字比较、确认提示不得出现在莲灯。莲灯将资源、收益、价格、缺口、操作与结果分区；按实际内容适应 PC 小窗口，保持角色可见、文字不溢出、按钮不重叠。验收必须包含“先打开两项取舍，再回到莲灯”、行囊往返和真实交易反馈，见 `docs/v19-lotus-layout-review.md`。

## v45 默认视野调整

按用户最新要求，默认进入全图规划；新开局、续档和新楼层到达采用相同默认。M 切换近观 / 全图，R 归位到悟空近观；同层移动及窗口调整保留玩家手动选择。入层确认、场景交互和战斗结算规则不变。实施与定向验收见 `docs/v45-default-map-review.md`。
