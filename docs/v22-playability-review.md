# v22 可玩性优化：实施与验收

2026-10-24。依据 [当前游戏可玩性分析](v20-playability-analysis.md) 和 [实施方案](v22-playability-plan.md)，优先完成 P0 与相关 P1 的完整使用链。保留十八层、有限资源、确定性战斗、两套画境、旧档、F 交互 / R 归位和离线直开。此次没有新增资源总量、随机伤害或跨局属性。

## 现在怎样使用

- **T：灯前推演。** 也可从行旅菜单进入，或选中场景目标后点“推演此处”。最多标记三个本层动作，可以调整顺序、保留方案甲，再与当前顺序比较。
- **短程成本。** 显示逐步资源变化、战斗损失、取舍支付、补给恢复、净变化和实际终点生命。沿途其他守卫、宝物和机关不会暗中处理。生命不足、缺钥、未解锁、未接通或顺序不成立时，在对应步骤停止并解释。失败方案显示中断处资源，不把它写成可完成的终点。
- **法器比较。** 在莲灯旁比较当前拥有的零至两件组合；六器全收集时有 22 组。比较使用同一目标序列，包含功德折损、神通费用和副作用。确认换装只改变行装，不执行计划，可用 Z 撤回。
- **章回前缘。** 保留六章的首次踏入状态及最近八次重大取舍前记录。先预览范围，再确认整份回退；后续资源、地图和任务一起撤回，绝不合并奖励。还保留本次回退前的完整进度，供返回一次；返回会舍弃试走分支。记录随自动、手动与导出存档保存。独立手动档不被自动回退覆盖。
- **熟路快行。** 点击寻路时，已走过、没有实体且不邻接事件的安全格使用更快节奏。依然逐格调用正式引擎；陌生路、敌人、封门、断口、机关附近保持原节奏。可在推演页关闭，Esc 随时中止。
- **此行所得。** 回看本会话最近的具体阶段结果，例如“十五层援手侧门接通”“经卷到手后仍需改驻甲乙”“卸栅保留青钥”。它只记录正式行动，推演不会制造完成记录。加载或回溯会清理本会话回看，正式任务仍由存档和因果簿保存。

## 合法路线与规则验收

1. **原战役不变。** 两条既有完整路线分别 4,142 / 3,850 次公开动作。从新游戏逐行动与 v21 备份引擎对比，原资源和进度字段一致；新增加的只是熟路记录和存档信封内的恢复档案。
2. **恢复不是复制资源。** 两条完整旅程均保留六章起点和七次实际取舍前记录。验证存取、整段替换、裁剪后续记录、返回原进度、分支再选、撤销/重做、旧档接续、非法记录拒绝、手动槽位保护。存档导入先验证记录，再替换当前状态。
3. **八层两解。** 从开局合法节省第一层可选宝龛的黄钥，抵达相同渡灯起点（生命 222，黄钥 1）。留桃路经普通渡口取得外舍利，保留黄钥；供灯路花该黄钥，走栈道取得同一舍利且不击杀西渡两只守卫。前者途中还取得其他成长，因此不能只比较终点生命来宣称优劣。
4. **十一层两解。** 从同一低生命、有限补给起点，分别取得攻击经或护心经。两条路线都合法调度分身、释放丙、保留甲乙并到达第十二层；攻击、防御、战损及用桃差异均来自实际行动。
5. **后段公开代价。** 十四层救援 / 修身与十七层留髓 / 燃髓的四个分支均从合法检查点结算一次。没有用资源注入或传送证明可玩。
6. **六器全组合。** 原路线走到首领战前，再合法行走 26 格回莲灯，对同一最终战比较 22 组已拥有组合；其中 10 组在该公开生命预算下可存活。其余显示缺口，不把不可存活方案结算成成功。

可复算记录：`audits/v22-playability-model.json`、`audits/v22-branch-routes.json`、`audits/v22-all-owned-gear.json`。对应脚本在 `tests/v22-*.cjs`。分支记录保留实际公开动作，不只保存最终数值。

## 测量解释

- 熟路 8 格的本机自动操作样本，普通约 0.9 秒、快行约 0.3 秒；同一组合法逐格结果一致。不是人类录像用时，不能据此宣称真人疲劳降低了固定比例。
- 新浏览器上下文、本地 HTTP、1440×900 的一次就绪测量约 0.7 秒。它包含当前本机与本地服务条件，不是互联网冷启动或低端机基准。
- 已拥有组合推演与正式动作持久化的耗时样本分别保存在全组合记录和模型记录；不将单次样本包装成稳定帧率承诺。本轮没有测到需要牺牲素材清晰度的加载问题。
