# v27 弹出界面排版修正

2026-10-24。依据用户提供的 629×678 要事牌截图，排查文字被边饰遮挡和按钮材质不协调。沿用 v26 已生成的四张实体材质，本轮修正实时文字、按钮、滚动和定位，不重新生成相同底图。

## 发现与修复

|问题|原因|实施|
|---|---|---|
|要事牌提示末尾挤在右下铜饰旁|按钮与提示争用一行；提示限制为 115px、右对齐，容器边界检查没有验证每行文字|按语义将提示分行，左侧提示、右侧动作，保留间隔；以素材可书写区域设置 30px 左右与底部留白，最小提示字为 11px。|
|矩形按钮与木铜牌、绢卷、经签不协调|主按钮沿用网站矩形底板，键帽又形成一个小方框|暗绢使用铜色刻线，纸面使用朱色刻线；移除嵌套方框与侧边实线，保留 42px 点击区、主次区分、禁用、悬停、按下与键盘焦点。取舍确认同样修正。|
|行囊说明的余量文字掉出底框|短窗口下纵向 flex 压缩签页，固定最小高度不足以容纳实际正文|签页不再压缩；行囊按内容排版，短 PC 窗口收紧物件展陈高度，窄面板将动作与说明并排，完整保留纸框。|
|详细经卷的末行进入底部装饰区|整张材质与内容一起滚动，边框不是独立的阅读边界|增加内层阅读区，只有正文滚动；外部框皮与四边留白固定。展开提醒、滚到卷末均纳入检查。|
|战斗规则展开后标题、正文贴边|历史 `.is-enemy.expanded` 高优先级规则将新素材内边距覆盖成 11px / 13px，并取消高度上限|为展开态明确同一书写留白与高度上限；正文只有一个滚动区。增加当前要事短句，展开阅读时收起重复的要事牌。|
|窄面板阅读区覆盖生命栏或与要事牌叠压|定位只做碰撞加权，隐藏对象仍可能参加障碍计算；未给展开阅读保留生存 HUD 区域|障碍只计可见元素；窄面板展开阅读位于顶部 HUD 下方，限制高度，检查生命栏与角色均无遮挡。|
|供签末行接近木框下沿|供签可点击内容的末行留白不足|增加供签底部安全区；实付、短缺与选择状态保持实时显示。|
|读档纸框未铺开、深色字落在背景上|旧“留”字印章的高优先级伪元素规则保留了偏移与内容，盖过新框皮|读档页明确重置装饰层的内容、四边、大小与切片；补查所有材质层的实际显示与覆盖范围。|

生产修改位于 `css/ui-layout.css`、`js/ui.js` 与 `index.html`。`scripts/build_v23_study.cjs` 更新当前入口版本，重新生成新版独立试玩页；冻结 v22 对照页不变。

## 覆盖范围与方法

17 类暂停视图：菜单、行囊、人物、画境、因果簿、图鉴、收集、指引、设置、读档、重新启程、力竭、觉醒、结局取舍、结局、灯前推演、独立试炼。

场景界面：常驻要事、详细楼层经卷、目标签页与战斗预览、展开规则与筹算、莲灯供签、两项与三项取舍、对白、入境、神通演出、最终三印决战、短提示与载入提示。额外覆盖推演账目、已拥有法器、禁用凝息珠操作、回溯预览、试炼完成和记录。

两套画境均检查 629×678、1280×720、1440×900、1989×1113。`tests/ui-layout-contract.cjs` 使用实时文字的 `Range.getClientRects()`，对照素材的装饰排除区域检查；不再只检查父容器。同步检查按钮文字溢出、提示与动作间隔、点击区域、展开态实际生存 HUD / 角色碰撞。长内容允许在内部阅读区滚动，检查初始和卷末状态，不要求所有内容同时显示。

真实交互使用独立浏览器进度和通过合法行动生成的存档。预览、选择、展开、取消保持状态一致；确认、购买、消耗品、神通跳过和回溯沿用实际引擎合同。原生应用内浏览器通过正常开局确认要事牌画面，保留 `UI27` 独立预览。
