# v29 人物交互入口简化

2026-10-24。依据用户两张点灯僧截图，修正“交谈 / 详察 / 推演此处”并列造成的困惑。

## 原因与实施

普通人物原本有两种阅读入口：“交谈”播放短对白，“详察”把完整剧情再次展开在签页里。共用目标模板未区分人物与机关，导致两种近似阅读行为并排，玩家无法判断应该先点哪一个。

- **人物只保留交谈，石碑只保留读碑。** 远处显示“走近交谈 / 走近读碑”，由真实安全路线接近；近处显示 F。完整背景保留在 J 手记的“塔中记事 / 此层同道与碑文”，移除人物与石碑的第二份详情阅读通道。
- **对白的继续与结束含义明确。** 使用“继续 / Space”和“结束交谈 / Esc”；读碑使用“停止读碑 / 读毕收卷”。末页只保留一个结束动作。结束后清除旧人物目标并恢复地图焦点，避免关闭横卷后又弹出同一张交谈卡。
- **推演只匹配目标本身的实际动作。** 原判断只比较坐标，人物恰好和玩家同格时，随身蟠桃或凝息珠的推演坐标会误命中人物。现在实体须匹配目标 id，不能把同坐标补给算成人物动作。
- **有实际作用的援手保留。** 白衣无天的“请开慈悲归路”会真实开启道路，与普通交谈有不同结果，因此保留该明确动作和对应真实推演；完成后不再提供待执行的推演。没有将剧情与开路合并为自动结算。
- **其他说明用内容命名。** 例如“物品说明”“开匣条件”“机关规则”“解印条件”，替代统一且含糊的“详察”。确认、支付和预览合同不变。
- **人物签页只显示一份当前目标。** 短卡的实际截图暴露要事牌遮住人物名的问题；查看人物或碑文时将当前目标放入签页，收起重复牌面，退出后恢复原场景目标。

生产修改位于 `js/ui.js`、`css/ui-layout.css`、`index.html`；新版试玩生成器更新 UI 版本。未修改引擎、地图、资源、战损、人物对白文本或援手结算规则。备份：`.backups/dialogue-v29-20261024/`。
