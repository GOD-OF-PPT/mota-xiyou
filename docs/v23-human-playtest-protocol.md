# 玩法深化真人试玩记录方法

本记录用于方案 S5 的真人观察。功能回归、合法路线脚本和模型运行不能填写为参与者结果。尚未收到真人记录时，分析脚本应输出“待观察”。

## 参与与任务

采用匿名编号，约 6–8 人，包含初次接触魔塔与有经验者。只记录实际参与者，不填虚构样本。主线首三层观察目标理解；同条件挑战观察八层路线和十一层驻守。

对照任务使用 [试玩准备入口](../playtest-v23.html)，填写匿名编号、任务、公开目标与轮次。首三层从正常开局开始；八层和十一层从合法战役行动生成的起点继续。两版资源预算相同，v22 运行冻结备份，v23 运行当前代码。两版都以主线任务模式完成上行，避免把 v23 的试炼结算界面和 v22 的主线体验混作同一任务。任务准备不算玩家行动，也不证明参与者能够自己抵达该层；全塔可达性另由合法战役记录证明。

入口使用三幅章回与目标题签，编号等字段在“本次行者”中，记录说明在“随行札记”中。当前新卷为 v23 玩法与 v26 imagegen 界面材质，v22 原卷仍冻结。两段请使用同一画境，入口会将选定画境带入两版；记录实际版本与当次 `research/study-v23/manifest.json` 源码清单，不能把不同界面修订的样本混作同一版。

编号末位奇数先 v22，偶数先 v23，仅作为平衡顺序的安排建议。记录实际顺序，不假定已经平衡。准备页可下载题目 ID、起点哈希、来源和 `budgetGroup`。记录时还要填写实际 `objective` 和 `round`；不同目标或轮次不合并计时。v22 起点缺少 v23 新增的结果账目字段，因此完整状态哈希不同；资源预算与进度已单独核对一致。

两版八层、十一层各有原版 / 新版任务入口，起点不依靠手改生命、钥匙或瞬移。准备信息的 `observedByHuman` 始终为 false。文件可直接打开，也可在当前本地服务器访问。刷新续接同一任务；改变编号、版本、任务、目标或轮次会开启独立存储。开始界面的“重置本段试玩”只清除本段记录，不影响其他任务或正式游戏。错误或缺失参数不会读取正式存档。

首三层在第三层归位三枚舍利并唤醒心印后结束；八层按指定保钥 / 供灯目标完成定风、舍利并上行后结束；十一层取得指定经卷、收回丙并以甲乙开路，上行后结束。任务说明不提供路线。独立试炼的目标区分与自发复玩另在 v23 游戏的正常试炼入口观察，与版本对照任务分开记录。

每段开始前不要提供最优路线。让参与者自行查看地图与公开条件；求助时记录提示内容和次数。结束后询问：你得到什么、付出什么、放弃什么；你刚改变了哪条路，之后可以怎样利用；是否愿意再试另一目标以及原因。尽量保留参与者原话。

## 计时

将思考、观察新信息、熟路执行分开记录，单位秒。纯执行时间只在任务和起始预算对应的原版 / 新版记录之间比较；不能把引擎动作数或自动寻路速度换算成人类疲劳。

若保存录像，先取得参与者同意，在本地记录引用即可；不上传个人信息或录像。无法区分的时间标为未知，不填零。

## 数据与分析

复制 `research/v23-human-study-template.json` 为新的记录文件。只有实际试玩 / 观察完成后才将 `observedByHuman` 设为 true，并填写匿名编号、经验、任务、题目哈希、目标、轮次、原话与观察判断。`null` 表示未知，不代表失败或零秒。准备页的 JSON 只是元数据，不能直接当成参与者记录提交。

运行 `python scripts/summarize_v23_human_study.py <记录文件> <输出文件>`。脚本输出参与人数、理解比例及具备有效配对计时的样本；不生成留存率，不替代人对原话是否合理的判断。

方案中的三分之二理解门槛、约 20% 纯执行时间下降，属于探索目标。样本不足或观察缺失时保留缺口；不为了使阶段通过而补齐推测数据。原始记录和方案判断应一并交回。

## 准备与技术核验

`node scripts/build_v23_study.cjs` 可重建两个试玩页和起点清单；清单在 `research/study-v23/manifest.json`，v22 的运行脚本与样式来自 `.backups/implementation-v23-20261024/`，共享本地素材。修改正式代码后须重新生成并核验入口；新一轮观察用新轮次，不能覆盖已完成的原始记录。

`audits/v23-study-browser.json` 记录六类启动、真实方向键、手动保存、刷新、独立命名空间、错误入口、正式存档字节保护以及 `file://` 离线验证。准备页与十一层画面已逐张按原尺寸复核。以上都是工具准备验收，不计入 S5 真人反馈。
