# v40 通关后的归途交互修复

2026-10-26。用户报告最终选择归途后仍停留在莲台签页，无法操作。

## 复现与根因

使用既有合法终局前存档，通过真实点击完成“选择归途 → 破劫归尘 → 略过演出 → 退出结局页 → 再点莲台”。修复前可稳定复现与截图一致的界面：仍写着“无骨归真 · 最后选择 / 选择归途 / 归真条件”，点击没有任何进展。

`audits/v40-before-fix.json` 保存修复前失败断言和调用探针。结局已经成功写入 `won=true`、`ending=release`；鼠标点击确实到达原来的 `moveTo(10,1)`，其返回 false。原因是界面缺少通关状态分支，依然尝试“走向莲台”；引擎正确拒绝改变已完成的冒险，因而没有再次发出 finale 事件。不是资源不足或输入遮罩残留，也不是结局未保存。

此前只验证“完成结局”，没有锁定“关闭结局后仍有可用入口”这段返回流程。

## 修正

- 莲台签页按通关状态显示“此行圆满 · 归途已定”，提供“重温结局 F / 返回标题”，移除过期的再次选择和归真条件。
- 已通关的莲台、F 和当前指引都直接打开已记录的结局，不再调用行走或重复 `finish()`。没有选中地图目标时，F 与指引按钮同样可用。
- 未通关的莲台使用其正式 `interact()` 入口；仍需满足原有相邻位置、五印、十六外舍利、击败三相和明确觉醒条件。
- 结局页提供“回看塔景 / 返回标题 / 再走一段因果”，顶部返回也明确为“回看塔景”。完成后的移动和施术栏收起，提示为“已通关 · F 重温结局”；确认新冒险时自动恢复。
- 没有解除引擎的通关保护，也没有修改战斗、奖励、地图、资源或存档格式。既有通关存档可直接恢复。正式入口和新版试玩同步 UI / journey 缓存版本 v40，冻结基线不变。

`tests/v40-ending-flow-browser.cjs` 的原问题路径修复前失败、修复后通过；完整结果为 `audits/v40-ending-flow.json`，当前源码与边界见 `audits/v40-final.json`。

- PC Chrome：玄金古寺与实际解锁后的青绿壁画，两种结局均通过。1280×720 与 629×678 检查结局页、实际文字与按钮的框皮安全范围。
- 结局选择只结算一次；生命、灵息、功德、凝息珠、钥匙、舍利与已完成物件不因结局选择额外改变。自然播放和 Space / Esc 跳过后，结局页仍可操作。
- 退出结局后依次验证：旧莲台动作重温、Esc 返回再按 F、清除地图目标后点击指引、无目标按 F、返回标题再继续前缘、刷新读取自动通关档。重温前后完整引擎快照一致，画境解锁保留。
