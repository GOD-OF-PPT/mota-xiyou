# v36 开门动作与说明分离

2026-10-26。依据用户青色封门两张截图，确认存在“开启封门”只切换说明、再次点击又收起说明的循环。真正的 `openDoor` 藏在展开区的另一个按钮里；同名动作实际含义不同。

## 修正结果

- 门签只有一份真实开门动作。已走近并选中门时，“用青钥开门 / F”直接调用 `engine.openDoor`，不再切换到另一个确认页面；开门前显示钥匙真实余额及预计变化，成功后显示实际消耗并返回地图。
- “开门说明”是文字折叠区，保留用途、永久通行、回溯和加入推演入口，不再包含第二个开门按钮。
- 远处明确写“走近封门 · 暂不开门”，只执行安全接近；到达后仍需明确用钥匙或神通开启。撞门和首次查看保留原来的预览行为，不会自动扣钥匙。
- 青蝉未觉醒时以文字说明第 6 层的解锁条件，移除无解释的灰色动作。觉醒后把“青蝉卸锁 · N 灵息”作为独立方法，说明它保留青钥；实际费用由引擎预览给出。
- 缺钥时明确显示“持有 0 把 · 尚缺 1 把”，禁用钥匙动作；F 不会扣除资源或弹出第二页。
- 成功后增加短暂的地图指针保护，防止双击的第二次指针事件穿透到地图、移动或再次支付。Esc 恢复地图焦点，Z 仍可准确回溯。
- 门签显示一份简短当前目标，收起外部重复要事牌，修正窄 PC 窗口中要事牌盖住开门按钮的情况。

未修改引擎、地图、费用、能力规则或存档格式。正式入口和新版试玩的 UI / 样式版本更新至 v36，冻结基线保持原字节。
